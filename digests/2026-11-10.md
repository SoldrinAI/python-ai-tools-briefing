# AI tools and libraries on Python: 2026-11-10

It's a quiet two days for Python AI releases. Most of what shipped is vendor SDK work, and the open source side had only a couple of releases worth your time.

## Enterprise tools

**[openai-python 3.49.0](https://github.com/openai/openai-python/releases/tag/v3.49.0)** (Nov 10). This release adds typed async function tools, so if you build agents on the OpenAI SDK, that's the part to read. The previous version, [3.48.0](https://github.com/openai/openai-python/releases/tag/v3.48.0) from Nov 9, added stream options for agent sessions.

```bash
pip install -U "openai==3.49.0"
```

**[anthropic 2.7.0](https://github.com/anthropics/anthropic-sdk-python/releases/tag/v2.7.0)** (Nov 9). It adds the `claude-fable-5-2` and `claude-mythos-5-2` model IDs. Most of the rest is fixes for the Bedrock and Vertex clients, including missing `parse` and `count_tokens` methods on the beta raw response wrappers. If you call Claude through a cloud provider, those fixes matter more than the new model IDs.

```bash
pip install -U "anthropic==2.7.0"
```

**[databricks-sdk 0.163.0](https://github.com/databricks/databricks-sdk-py/releases/tag/v0.163.0)** (Nov 9). The files endpoint order is now on by default, with a fallback to the old order if the workspace gives no usable answer. POST requests also stop retrying after a read timeout, because the server may already have handled the first attempt. If your code relies on automatic retries for writes, check that path.

```bash
pip install -U "databricks-sdk==0.163.0"
```

## Open source libraries

**[litellm 1.108.4](https://github.com/BerriAI/litellm/releases/tag/v1.108.4)** (Nov 9). This is marked as an LTS release. It fixes Bedrock 400 errors when a conversation includes Claude's signed thinking, and a Vertex AI batch 404. It also fixes a bug present since v1.106.0 where `completion()` and tool calls failed on a base install with `No module named 'mcp'`.

```bash
pip install -U "litellm==1.108.4"
```

**[langchain-core 1.7.7](https://github.com/langchain-ai/langchain/releases/tag/langchain-core==1.7.7)** (Nov 10). This is a small release, but it caps nesting depth when `load()` rebuilds serialized objects. If your code loads serialized data from outside your own systems, pull it in.

```bash
pip install -U "langchain-core==1.7.7"
```

## Worth trying today

Install `litellm==1.108.4` into a fresh virtualenv with no extras, then run `python -c "import litellm"` and a single completion call. It's a quick way to see whether your base install still hits the missing `mcp` import.
