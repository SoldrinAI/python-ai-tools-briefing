# AI tools and libraries on Python: 2026-11-25

Two days, a handful of releases that actually changed something. The Anthropic and OpenAI SDK updates both touch behavior you might rely on, and pydantic-ai and LiteLLM shipped new versions with notes worth reading. I left out anything I couldn't tie to a release page.

## Enterprise tools

**[Anthropic Python SDK 2.14.0](https://github.com/anthropics/anthropic-sdk-python/releases/tag/v2.14.0)** (Nov 24). The change to read first is proxy handling. The client used to read `HTTP_PROXY`, `HTTPS_PROXY` and `NO_PROXY` even when you passed `proxy=`, and now an explicit `proxy=` wins for every request. If you list a host in `NO_PROXY` and also pass `proxy=`, that host now goes through your proxy. The release also adds Google-managed data controls and compliance review support.

```bash
pip install -U "anthropic==2.14.0"
```

**[OpenAI Python SDK 3.59.0](https://github.com/openai/openai-python/releases/tag/v3.59.0)** (Nov 24). Healthcare model IDs for the Responses API are new. The fixes are the ones that matter in production: credential headers are now redacted from API error requests, empty webhook signing keys are rejected, and beta Realtime sessions use bearer auth.

```bash
pip install -U "openai==3.59.0"
```

**[Strands Agents SDK 1.66.0](https://github.com/strands-agents/sdk-python/releases)** (Nov 23). The first change listed is that `agent.cancel()` now stops running `shell` and `python_repl` commands. If you let an agent run shell commands, that is a useful fix to have. I only checked the release list for this one, so read the full notes before you rely on the details.

```bash
pip install -U "strands-agents==1.66.0"
```

**[Databricks SDK for Python 0.170.0](https://github.com/databricks/databricks-sdk-py/releases/tag/v0.170.0)** (Nov 23). For AI work, Vector Search and AI Search endpoints get a `finalizing` scaling phase, and `ml.Function` gains `lookup` and `secondary_keys` fields. The Lakewatch `Rule.schedule` field is no longer required, and the notes flag that change as breaking.

```bash
pip install -U "databricks-sdk==0.170.0"
```

## Open source libraries

**[pydantic-ai 2.74.0](https://github.com/pydantic/pydantic-ai/releases/tag/v2.74.0)** (Nov 24). The big addition is a core `computer` tool contract, plus `ComputerUse()` support across OpenAI, Claude and Gemini, and desktop support for several sandboxes. Read the compatibility notes before you upgrade. Gemini streaming through `OpenAIChatModel` now reports final usage totals instead of their sum, so cost figures drop and `UsageLimits` token limits trigger later.

```bash
pip install -U "pydantic-ai==2.74.0"
```

**[LiteLLM 1.110.3](https://github.com/BerriAI/litellm/releases/tag/v1.110.3)** (Nov 24), with a follow-up patch in **[1.110.4](https://github.com/BerriAI/litellm/releases/tag/v1.110.4)** (Nov 25). The 1.110.3 notes have an action item: gateway-owned MCP client registration is now opt-in, so set `LITELLM_MCP_DCR_GATEWAY_CLIENT=true` if you rely on it. The fixes also cover per-model fallbacks for complexity routing and a 500 on `GET /audit`. The 1.110.4 patch is mostly security hygiene: automated OSV and grype scans on the stable line, plus nginx and zlib updates in the UI image.

```bash
pip install -U "litellm==1.110.4"
```

**[OpenAI Agents SDK 0.26.0](https://github.com/openai/openai-agents-python/releases/tag/v0.26.0)** (Nov 24). Read the "may need action" section before upgrading. Docker now rejects in-container storage mounts, including read-only ones, so sessions that use them need a new session with an updated manifest. An input guardrail rejection now also stops queued function tools, which is the behavior you probably wanted anyway.

```bash
pip install -U "openai-agents==0.26.0"
```

**[Transformers 5.24.1](https://github.com/huggingface/transformers/releases/tag/v5.24.1)** (Nov 24). A patch release. Most of it unblocks vLLM with remote code, plus fixes for a Llama4 forward crash and expert parallelism when `tp_plan={}`.

```bash
pip install -U "transformers==5.24.1"
```

## Worth trying today

If you pass `proxy=` to the Anthropic client, check what it does with your `NO_PROXY` list. A quick way to see it is to point a client at a proxy you can watch and send one request.

```python
from anthropic import Anthropic, DefaultHttpxClient

client = Anthropic(
    http_client=DefaultHttpxClient(proxy="http://127.0.0.1:8080"),
)
print(client.messages.create(
    model="claude-haiku-5-5",
    max_tokens=20,
    messages=[{"role": "user", "content": "Say hi."}],
).content[0].text)
```

Run it with your proxy logging on. If the request shows up there, your `NO_PROXY` entries are no longer bypassing it.
