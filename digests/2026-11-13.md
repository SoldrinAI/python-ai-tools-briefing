# AI tools and libraries on Python: 2026-11-13

Two days of point releases, and the one that can break running code is Databricks 0.166.0, which makes a field required on one of its AI function classes. Pydantic AI 2.68.0 is the other release to read before upgrading, since it renames several event classes.

## Enterprise tools

**[databricks-sdk 0.166.0](https://github.com/databricks/databricks-sdk-py/releases/tag/v0.166.0)** (Nov 12). The breaking change is `output_ref` on `aifunctions.Batch`, which is now required. The `expired` value is also gone from `aifunctions.BatchStatus`, and `continuous` is removed from `lakewatch.RuleSchedule`. The release adds a `w.assume_group` service, so if you run code on Databricks, search your repo before you upgrade.

```bash
pip install -U "databricks-sdk==0.166.0"
```

**[google-genai 3.3.0](https://github.com/googleapis/python-genai/releases/tag/v3.3.0)** (Nov 12). `ThinkingLevel` gains an `XHIGH` value, and the `Model` enum now lists `gemini-4-hydrogen` for interactions. The notes don't list breaking changes, though the README was updated to cover the breaking changes from the v3 line. If you set thinking levels by hand, the new value is worth a try.

```bash
pip install -U "google-genai==3.3.0"
```

**[azure-ai-projects 2.11.0](https://pypi.org/project/azure-ai-projects/2.11.0/)** (Nov 13). Voice agents and external agents are now generally available, and agent creation from a prompt is available as `.agents.create_from_prompt()`. This release moves several `.beta` operations to non-beta paths, so calls to `.beta.agents.create_from_prompt()` and `.beta.voice_agents.*` will need updating. Most of the new surface is in Microsoft Foundry projects, so the change matters most if you already use that stack.

```bash
pip install -U "azure-ai-projects==2.11.0"
```

## Open source libraries

**[pydantic-ai 2.68.0](https://github.com/pydantic/pydantic-ai/releases/tag/v2.68.0)** (Nov 12). The new pieces are `ConversationStore` for saving UI conversations, a `GoogleDecisionsModel` backend, and `RequestInput` for asking for approvals inside a run. `ModelFallback` now moves to the next model when a response is cut off at `max_tokens`, which is handy if you have a fallback chain. The compatibility notes are longer than usual, so read them: sub-agent events get new names with deprecated aliases, and `num_results` becomes `max_results` in `pydantic_ai_harness`.

```bash
pip install -U "pydantic-ai==2.68.0"
```

**[langchain 1.5.0](https://github.com/langchain-ai/langchain/releases/tag/langchain%3D%3D1.5.0)** (Nov 11). The headline is `ModelRouterMiddleware`, which is marked beta and adds model routing and auto mode. The release also drops Python 3.10, so the floor is now 3.11. The notes are mostly PR titles, so you will need to read the source to know how routing decisions get made before you rely on it.

```bash
pip install -U "langchain==1.5.0"
```

**[crewAI 1.15.41](https://github.com/crewAIInc/crewAI/releases/tag/1.15.41)** (Nov 12). The feature lets you approve private URL hosts, which matters if your agents read internal pages. Two fixes are worth knowing about: earlier step outputs now survive a human-feedback resume, and the `cache_breakpoint` marker is stripped on the LiteLLM path. The projects also move to PyMuPDF 2.x.

```bash
pip install -U "crewai==1.15.41"
```

## Worth trying today

Databricks made `output_ref` required on `aifunctions.Batch`, so any batch job you wrote against the old release needs an `output_ref` now. Search your repo for the names that changed and see what you find.

```bash
grep -rn "aifunctions\|BatchStatus\|RuleSchedule" --include="*.py" .
```
