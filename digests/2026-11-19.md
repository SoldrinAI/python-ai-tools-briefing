# AI tools and libraries on Python: 2026-11-19

Most of today's releases landed on November 18, since yesterday's digest already covered the November 16 and 17 batch. The breaking changes are the part to read first this round, because LiteLLM and openai-agents both removed or changed defaults.

## Enterprise tools

**[Databricks SDK for Python v0.168.0](https://github.com/databricks/databricks-sdk-py/releases/tag/v0.168.0)** (Nov 18). The new piece is a `w.lakewatch` workspace service with parser management methods. The release also adds `detailed_state` to AI Search and Vector Search index status objects, which is handy if you poll index readiness. Two breaking changes to check: `jobs.SqlConditionConfiguration.sql_query_id` is no longer required, and the `migration_type_online` value was removed from `postgres.MigrationType`.

```bash
pip install -U databricks-sdk==0.168.0
```

**[OpenAI Python SDK v3.55.0](https://github.com/openai/openai-python/releases/tag/v3.55.0)** (Nov 18). The API addition is Live MCP server configuration, which is the one to read if you connect models to MCP servers. The same release hides the Managed Agents session budget controls and events. There is also a v3.55.1 on PyPI from the same day that I didn't open, so read its notes before you pin.

```bash
pip install -U openai==3.55.0
```

**[Google Gen AI SDK v3.5.0](https://github.com/googleapis/python-genai/releases/tag/v3.5.0)** (Nov 18). This adds a self-hosted BYOS mode for environments, with `system_instruction`, `custom_config` and `environment_key` supported across the SDKs and CLI. It also brings Live Interactions over WebSocket and WebRTC, which the notes mark as experimental. The Live API and caches are not available on v1, so check your client version if you use them. v3.6.1 followed the same day with a single enum fix, so install that one.

```bash
pip install -U google-genai==3.6.1
```

## Open source libraries

**[LiteLLM v1.110.0](https://github.com/BerriAI/litellm/releases/tag/v1.110.0)** (Nov 18). This is a large release. A Rust router core now sits in front of the proxy, and the Python router core is gone. If you run the proxy, the error changes matter most: upstream overloads come back as 503 `server_is_overloaded` on OpenAI routes, and upstream Anthropic 529s pass through on `/v1/messages`. Cost logging now carries the per-call price on the logging object instead of writing to `litellm.model_cost`, and the SpendLogs ledger is the default accounting path. Test any code that parses those errors or reads spend data before you roll it out.

```bash
pip install -U litellm==1.110.0
```

**[openai-agents 0.25.0](https://github.com/openai/openai-agents-python/releases/tag/v0.25.0)** (Nov 18). The beta Runloop sandbox provider has been removed. If you used it, back up your workspace data and plan a move to another provider, or stay on 0.24.0. The default model for `OpenAIResponsesCompactionSession` is now `gpt-6-luna`, so pass `model="gpt-4.1"` if you want the old behavior. Handoffs also accept a `failure_error_function` for opt-in recovery, and MCP v2 Streamable HTTP now handles concurrent requests.

```bash
pip install -U openai-agents==0.25.0
```

**[CrewAI 1.15.42](https://github.com/crewAIInc/crewAI/releases/tag/1.15.42)** (Nov 18). ChromaDB is now an optional extra rather than a default dependency, and knowledge defaults to a local Qdrant store. If your crews rely on Chroma being installed, check that before you upgrade. Most of the rest is bug fixes, including one that makes `max_execution_time` take effect without waiting for the worker. The release also raises the minimum soupsieve to 4.0 to address CVE-2026-126190.

```bash
pip install -U crewai==1.15.42
```

**[langchain-core 1.8.3](https://github.com/langchain-ai/langchain/releases/tag/langchain-core%3D%3D1.8.3)** (Nov 18). This is a small patch. Warning suppression is now context-local, so it applies only inside the context that set it. It also picks up a dev-dependency update. Upgrading should be uneventful.

```bash
pip install -U langchain-core==1.8.3
```

## Worth trying today

Search your code for anything these releases removed or renamed. It takes a few seconds, and it tells you whether an upgrade is a version bump or needs real changes.

```bash
grep -rniE "runloop|model_cost|migration_type_online|sql_query_id" --include="*.py" .
```
